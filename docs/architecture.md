## データフロー

### 1. ユーザー認証フロー

```
ブラウザ
  │
  │ ① メール/パスワード送信
  │
  ▼
Amazon Cognito User Pool
  │
  │ ② JWT Token発行
  │
  ▼
Amazon Cognito Identity Pool
  │
  │ ③ 一時認証情報発行 (AssumeRoleWithWebIdentity)
  │    • AccessKeyId
  │    • SecretAccessKey
  │    • SessionToken
  │    • Expiration (1時間)
  │
  ▼
ブラウザ (AWS SDK自動管理)
  │
  └─► 以降、全AWSサービス呼び出しにこの認証情報を使用
```

### 2. クエリ実行フロー

```
ブラウザ
  │
  │ ① 自然言語クエリ入力
  │    例: "11/15の課金額トップ10を教えて"
  │
  ▼
lib/bedrock.ts (ブラウザ実行)
  │
  │ ② Bedrock API呼び出し (直接)
  │    - リージョン: us-east-1
  │    - モデル: amazon.nova-pro-v1:0
  │    - 認証: Cognito一時認証情報
  │
  ▼
Amazon Bedrock
  │
  │ ③ SQL生成 + 説明文生成
  │    {
  │      "sql": "SELECT player_id, SUM(purchase_amount) ...",
  │      "explanation": "課金額の多い順に..."
  │    }
  │
  ▼
lib/s3-utils.ts (ブラウザ実行)
  │
  │ ④ S3 Signed URL生成 (直接)
  │    - GetObjectCommand
  │    - 有効期限: 30分
  │    - 認証: Cognito一時認証情報
  │
  ▼
Amazon S3
  │
  │ ⑤ Signed URL返却
  │    https://bucket.s3.amazonaws.com/logs/.../logs-10.parquet?...
  │
  ▼
lib/duckdb.ts (ブラウザ実行)
  │
  │ ⑥ Parquetファイルダウンロード (fetch API)
  │    - 並列ダウンロード (最大480ファイル)
  │    - バイナリデータ取得
  │
  ▼
DuckDB WASM (ブラウザ内)
  │
  │ ⑦ Parquetファイル読み込み
  │    - registerFileBuffer()
  │    - CREATE TABLE ... FROM read_parquet()
  │    - INSERT INTO ... (2ファイル目以降)
  │
  │ ⑧ SQL実行
  │    - クエリ解析
  │    - 列指向データ処理
  │    - 集計・ソート
  │
  ▼
components/QueryResult.tsx
  │
  │ ⑨ 結果表示
  │    - テーブル表示
  │    - グラフ自動生成 (Recharts)
  │    - CSVエクスポート
  │
  ▼
lib/conversation-history.ts
  │
  │ ⑩ LocalStorage保存
  │    - クエリ履歴
  │    - 結果データ
  │    - 最大50件
```

## IAMポリシー構成

### 認証済みユーザーロール

すべての認証済みユーザーに付与される基本権限:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "bedrock:InvokeModel"
      ],
      "Resource": [
        "arn:aws:bedrock:us-east-1::foundation-model/amazon.nova-pro-v1:0",
        "arn:aws:bedrock:*:*:inference-profile/us.amazon.nova-pro-v1:0"
      ]
    },
    {
      "Effect": "Allow",
      "Action": [
        "s3:GetObject",
        "s3:ListBucket"
      ],
      "Resource": [
        "arn:aws:s3:::amplify-llmloganalyzer-*",
        "arn:aws:s3:::amplify-llmloganalyzer-*/*"
      ]
    }
  ]
}
```

### チーム別ロール

各Cognitoグループに自動的に付与:

- **team-alpha**: team-alphaのログのみアクセス可能
- **team-beta**: team-betaのログのみアクセス可能
- **team-gamma**: team-gammaのログのみアクセス可能
- **team-admin**: 全チームのログにアクセス可能

### 判定基準

**Amplify枠内に含めるリソース**:
- ✅ `amplify/backend.ts`の`defineBackend()`で定義されている
- ✅ `npx ampx sandbox`または`npx ampx pipeline-deploy`でデプロイされる
- ✅ `amplify_outputs.json`に記載される
- ✅ Amplify CLIが自動的にプロビジョニング・管理する

**Amplify枠外に配置するリソース**:
- ❌ `amplify/backend.ts`で定義されていない
- ❌ IAMポリシーで**権限のみ付与**され、リソース自体はAmplifyが作成しない
- ❌ 手動セットアップが必要
- ❌ ブラウザから直接アクセスするが、Amplifyが管理しない

### 重要な注意点

1. **CloudFrontとS3ホスティングバケット**: セットでAmplify Hostingが自動作成するため、**両方ともAmplify枠内**

2. **S3ログバケット**: `defineStorage()`で定義されているため、**Amplify枠内**

3. **IAMロール**: Amplify Gen 2が自動的に作成・管理するため、**Amplify枠内**

4. **Bedrock**: `backend.ts`でIAMポリシーを定義しているが、Bedrockリソース自体はAWS標準サービスとして存在するため、**Amplify枠外**

5. **IAMポリシー**: Amplify管理リソースに対する権限設定なので、**Amplify枠内の各リソースに付随**

## セキュリティ構成

### 多層防御アーキテクチャ

```
Layer 1: ネットワーク
  └─ CloudFront + HTTPS強制
  
Layer 2: 認証
  └─ Cognito認証 (JWT Token)
  
Layer 3: 認可
  └─ IAMロール + ポリシー
  
Layer 4: データアクセス
  └─ S3 Signed URL (30分期限)
  
Layer 5: データ処理
  └─ ブラウザ内処理 (DuckDB WASM)
```

### データフロー制御

- **S3バケット**: プライベート (直接アクセス不可)
- **CloudFront**: S3へのアクセス制限 (OAI)
- **Signed URL**: 短期間のみ有効
- **IAMポリシー**: チーム別アクセス制御

## スケーラビリティ

### 自動スケール要素

| コンポーネント | スケーリング方式 |
|--------------|----------------|
| CloudFront | 自動 (グローバルエッジ) |
| S3 | 自動 (無制限) |
| Cognito | 自動 (MAU課金) |
| Bedrock | 自動 (リクエストごと課金) |

### パフォーマンス最適化

1. **CloudFrontキャッシュ**
   - 静的ファイル: 1年
   - HTML: 1時間

2. **DuckDB WASM**
   - ブラウザ内並列処理
   - カラムナー形式による高速クエリ

3. **Parquet形式**
   - 圧縮率: 70-90%
   - クエリ速度: JSONL比5-10倍高速

4. **データロード最適化**
   - 一度のロードで複数クエリ実行
   - テーブルキャッシュ
