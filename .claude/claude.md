# Claude開発ガイドライン

このファイルは、Claude Code (AI)がこのプロジェクトで開発を行う際の指針を記載しています。

## テスト駆動開発 (TDD)

### 基本方針

**コード変更時には必ずテストコードも作成・実行すること**

1. **新機能実装時**
   - コンポーネントやユーティリティ関数を実装後、必ずテストコードを作成
   - テストを実行して全てがパスすることを確認

2. **既存コード修正時**
   - 影響範囲のテストが存在するか確認
   - 存在しない場合は新規作成
   - 修正後、必ずテストを実行して回帰バグがないことを確認

3. **テストの配置**
   - コンポーネントテスト: `components/__tests__/` または `components/ui/__tests__/`
   - ユーティリティテスト: `lib/__tests__/`
   - ページテスト: `app/**/__tests__/`

### テスト実行コマンド

```bash
# 全テスト実行
npm test

# ウォッチモード（開発中推奨）
npm run test:watch

# カバレッジ付き実行
npm run test:coverage
```

### テストカバレッジの目標

- **新規コンポーネント**: 80%以上
- **UI基本コンポーネント**: 90%以上
- **クリティカルなロジック（認証、データ処理等）**: 80%以上

### テストツール

- **Jest**: テストランナー
- **React Testing Library**: コンポーネントテスト
- **@testing-library/user-event**: ユーザーインタラクションのシミュレーション

### テスト作成のガイドライン

1. **ユーザー視点でテストを書く**
   - DOM構造ではなく、ユーザーが見える要素（テキスト、ラベル、ロール）で検索
   - 実装の詳細に依存しないテストを心がける

2. **各テストは独立させる**
   - テスト間で状態を共有しない
   - beforeEach/afterEachで適切にクリーンアップ

3. **モックは最小限に**
   - 外部依存（AWS Amplify等）のみモック
   - できる限り実際のコンポーネントの動作をテスト

4. **わかりやすいテスト名**
   - 日本語で「何をテストしているか」を明確に記述
   - 例: `"送信ボタンをクリックするとonSubmitが呼ばれる"`

### テストすべき項目

#### UIコンポーネント
- [ ] 初期表示が正しいか
- [ ] ユーザーインタラクション（クリック、入力等）が正しく動作するか
- [ ] 状態変化が正しく反映されるか
- [ ] エラー状態が適切に表示されるか
- [ ] プロパティによる表示切り替えが正しいか

#### ユーティリティ関数
- [ ] 正常系の動作
- [ ] 異常系（エラー）の処理
- [ ] エッジケース（空文字、null、undefined等）

#### 認証・データ処理
- [ ] 認証状態の判定
- [ ] 権限チェック
- [ ] データ変換・検証ロジック

## プロジェクト固有の注意事項

### AWS Amplify関連

- Amplifyの関数は必ずモックしてテスト
- 実際のAWSリソースへの接続は行わない

```typescript
jest.mock("aws-amplify/auth", () => ({
  getCurrentUser: jest.fn(),
  fetchAuthSession: jest.fn(),
  signOut: jest.fn(),
}));
```

### Next.js App Router

- `useRouter`などのNext.js固有のフックもモックが必要
- テスト環境では実際のルーティングは発生しない

```typescript
jest.mock("next/navigation", () => ({
  useRouter: jest.fn(),
}));
```

## 継続的な改善

テストコードも実装コードと同様に継続的に改善していく：

1. **テストが失敗したら**
   - 実装の問題かテストの問題かを見極める
   - テストが不適切なら、テストコードを改善

2. **重複を見つけたら**
   - 共通のテストヘルパーやモックを作成
   - DRY原則をテストコードにも適用

3. **カバレッジが低い箇所を見つけたら**
   - 優先度の高い機能から順にテストを追加
   - 100%を目指すのではなく、重要な部分を重点的にカバー
